# Brief T004 — rework 2 (el Reviewer devolvió FAIL)

El template está bien construido y varios tests son genuinamente buenos: el del toggle ejercita clics y comprueba `aria-expanded` **y** `data-collapsed` en ambos sentidos; el de query params verifica `detalle=subC01t`, o sea la clave y no el texto traducido. Nada de eso se toca.

Se devuelve por **tres defectos**. Corrige solo esto.

## Defecto 1 — los selectores con coma anulan el gate (el más importante)

El template emite **dos vocabularios de clases a la vez**:

```html
<ul class="subs svc-subs" ...>
<p class="chapter__note svc-note">
<article class="chapter svc-group" ...>
<aside class="rail toc" ...>
<section class="closer svc-actions">
```

y los tests preguntan por ambos:

```ts
article.querySelectorAll('.subs li, .svc-subs li')
riesgo.querySelector('.chapter__note, .svc-note')
root.querySelector('.closer a.btn--gold, .svc-actions a.btn--gold')
```

Un selector con coma casa si existe **cualquiera** de los dos. Resultado: el test **no fija ninguno de los dos contratos**. Si T006 elimina `.subs`, sigue verde por `.svc-subs`; si elimina `.svc-subs`, sigue verde por `.subs`. Eso es exactamente la clase de defecto DC-6 que este spec existe para cerrar: una aserción que no puede distinguir no es evidencia.

Además, arrastrar dos nombres para cada cosa deja a T006 con dos vocabularios que estilar, y el CSS del mockup usa solo el nuevo.

**Arreglo requerido:**
- Elimina **todas** las clases heredadas del template: `svc-subs`, `svc-note`, `svc-group`, `svc-actions`, `toc`, y cualquier otra que dupliques. Queda un solo nombre por elemento, el del mockup (`subs`, `chapter__note`, `chapter`, `closer`, `rail`).
- Elimina **todas** las comas de los selectores en los tests. Cada aserción apunta a un único selector.

## Defecto 2 — número de WhatsApp duplicado con un fallback inalcanzable

```ts
private readonly whatsappNumber = inject(WHATSAPP_NUMBER, { optional: true }) ?? '573248805290';
```

`WHATSAPP_NUMBER` está declarado `providedIn: 'root'` **con factory**, así que nunca puede faltar: `optional: true` no se activa jamás y el `?? '573248805290'` es código muerto. Pero es un literal que duplica una constante cuya propia configuración dice, textualmente, que se centralizó *"para que el formulario de contacto comparta exactamente el mismo token"*. Los otros dos consumidores (`contact-section.ts`, `whatsapp-fab.ts`) hacen `inject(WHATSAPP_NUMBER)` a secas.

**Arreglo requerido:**

```ts
private readonly whatsappNumber = inject(WHATSAPP_NUMBER);
```

Sin `optional`, sin literal. Un solo sitio donde vive el número.

## Defecto 3 — métodos muertos

```ts
getMoreLabel(group: ServiceGroup): string { return this.moreLabel()(group); }
getQuoteLabel(group: ServiceGroup): string { return this.quoteLine()(group); }
```

El template llama directamente a `moreLabel()(group)` y `quoteLine()(group)`. Estos dos métodos no los usa nadie. Es el mismo patrón de superficie especulativa por el que ya se devolvió T002.

**Arreglo requerido:** elimínalos.
