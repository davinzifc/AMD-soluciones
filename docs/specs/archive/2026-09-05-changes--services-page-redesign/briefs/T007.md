## Contrato de comportamiento

La página de Servicios navega a Home, fragmento `contacto`, con parámetros de consulta:

- desde una fila de sub-servicio: `servicio=<id de grupo>` y `detalle=<clave i18n del título>`
- desde el CTA de una línea: solo `servicio=<id de grupo>`

El formulario de contacto debe recibirlos y llegar preparado:

1. Si `servicio` corresponde a un grupo de servicio válido, queda **preseleccionado** en el campo de servicio de interés.
2. Si `servicio` trae cualquier otro valor, **se ignora en silencio**: el formulario queda como estaba y no se lanza ningún error.
3. Si viene `detalle`, el sub-servicio queda **identificado en el contenido prellenado del mensaje**.
4. `detalle` llega como **clave de i18n, nunca como texto traducido**: debe localizarse al mostrarse, de modo que **sobreviva a un cambio de idioma**.
5. **No** se llama a ninguna API ni se persiste nada: la fase 1 no tiene backend.
6. No se emite analítica nueva.
7. Sin parámetros, el comportamiento actual del formulario queda **exactamente igual**.

## Tests
