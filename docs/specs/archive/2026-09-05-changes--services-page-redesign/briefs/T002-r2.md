## Defecto 1 — `return '' as T` viola el contrato

`active-chapter.ts` hace:

```ts
if (chapters.length === 0) {
  return '' as T;
}
```

El Done-when de T002 dice: *"Nunca devuelve `undefined`/vacío: siempre exactamente un id."* Una cadena vacía **es** el caso vacío, disfrazado con un cast que miente al compilador. Aguas abajo, T005 escribiría `aria-current` sobre un id inexistente y el índice quedaría sin ninguna línea marcada — el fallo que REQ-001 prohíbe explícitamente.

Y tu propio test lo esquiva:

```ts
it('never returns undefined, null, or empty string for non-empty lists', ...)
```

El calificativo *"for non-empty lists"* recorta la invariante justo alrededor del único caso donde se rompe. Un test moldeado sobre el defecto no es evidencia.

**Arreglo requerido — hazlo imposible en tipos, no en runtime:**

```ts
export function resolveActiveChapter<T extends string = string>(
  chapters: readonly [ChapterPosition<T>, ...ChapterPosition<T>[]],
  readingLine: number,
  atBottom: boolean,
): T
```

Con una lista no vacía a nivel de tipo, la rama del `length === 0` desaparece: no hay cast, no hay retorno vacío, y el compilador rechaza la llamada incorrecta. Elimina el `if` y el `as T`.

No lances excepción: esta función corre dentro de un manejador de scroll y un throw rompería la página. La ausencia de capítulos se maneja en T005 con una guarda antes de llamar.

Actualiza el test de invariante: quita el calificativo *"for non-empty lists"*, que ya sobra.

## Defecto 2 — API especulativa

```ts
export const getActiveChapter = resolveActiveChapter;
export const pickActiveChapter = resolveActiveChapter;
```

Nadie pidió alias. Triplican la superficie pública de una función y obligan a un futuro lector a averiguar si difieren. El test que los acompaña —afirmar que un alias devuelve lo mismo que aquello a lo que apunta— es tautológico: no puede fallar y no prueba comportamiento.

**Arreglo requerido:** elimina ambos alias y su test. Queda un solo nombre exportado: `resolveActiveChapter`.
