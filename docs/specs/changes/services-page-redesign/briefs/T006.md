## Qué hacer

Porta el CSS del mockup al componente. Es un port, no un rediseño: el mockup ya pasó revisión visual.

**Diferencias obligatorias respecto al mockup:**

1. El mockup es una página suelta con `body { … }` y `.topbar` propios. Aquí el CSS está **scopeado al componente**: usa `:host` para la superficie de la página. **No** estilices `body`, `html` ni el nav — el nav lo pone el layout de la app.
2. **DD-024 — los cuatro valores derivados (`--ink-text`, `--ink-text-2`, `--ink-text-3`, `--hairline`) se declaran en `:host`**, nunca en `tokens.css`. Promoverlos al sistema global es un cambio al design system que este spec no autoriza.
3. El colapso: el mockup usa `[data-collapsed='true'] [data-overflow='true'] { display: none }`. El template real emite esos mismos atributos — respétalos exactamente.

**Requisitos que el CSS debe cumplir:**

- **REQ-002:** `scroll-behavior: smooth` en el documento y `scroll-margin-top` en `.chapter` para que el `<h2>` quede visible bajo el nav sticky. Bajo `prefers-reduced-motion: reduce`, `scroll-behavior: auto` y transiciones desactivadas.
  Ojo: `scroll-behavior` sobre el documento **no** se puede aplicar desde `:host`. Ponlo donde corresponda sin romper el scope del componente; si necesitas alcance global, usa el sitio que el repo ya use para eso y **documenta por qué** en un comentario.
- **REQ-009:** índice en columna sticky ≥1100px; chips horizontales por debajo; filas a 1 columna <720px; **sin scroll horizontal de página** entre 375px y 1440px.
- **REQ-009 / KZ-002:** **ningún selector con ancestro `body` o `html` para mostrar u ocultar.** Solo media queries. Esta lección viene de un defecto real ya cometido en este repo.
- **REQ-010 / KZ-001:** todos los objetivos táctiles ≥44px y foco visible en dorado de marca. No reduzcas ninguna geometría de control existente.
- **REQ-011:** cero colores fuera de los tokens AMD. Cero `#673de6`, `#5025d1`, `#8c85ff`.
